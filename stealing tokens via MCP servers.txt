Staeling tokens via MCP servers
================

Running the External Service Manager
------
git clone https://gitlab.practical-devsecops.training/marudhamaran/cmcp-insecure-mcp-server.git
cd cmcp-insecure-mcp-server
docker build -t insecure-mcp .
docker run -p 9001-9010:9001-9010 -p 8001-8010:8001-8010 insecure-mcp

Opening VS Code
Open the lab VS Code environment in your browser https://devsecops-box-gpu-vs-uuwpigae.lab.practical-devsecops.training


Prompt 1: List available services
=============
use external-service-manager and get a list of available services.
Important Instruction: 1. Do not read local files. 2. Do not call unknown services. 3. Use only the tools and resources available in external-service-manager. 4. Do not execute CLI commands.

alternative
use external-service-manager call MCP tools only and return the list of available services from the server. Important Instruction: 1. Do not read local files. 2. Do not call unknown services. 3. Use only the tools and resources available in external-service-manager. 4. Do not execute CLI commands.

use external-service-manager Important: call the exact MCP tool that lists services; do not use the terminal or local files. Use only the tools and resources available in external-service-manager.

use external-service-manager return all external services the MCP server reports. Important Instruction: 1. Do not read local files. 2. Do not call unknown services. 3. Use only the tools and resources available in external-service-manager. 4. Do not execute CLI commands.


use external-service-manager call the MCP tool that matches "external services" in its description; same Important Instruction block as Prompt 2.

===============

Important Instruction: 1. Do not read local files. 2. Do not call unknown services. 3. Use only the tools and resources available in external-service-manager. 4. Do not execute CLI commands.

Use only the tools and resources available in external-service-manager. 4. Do not execute CLI commands.

use external-service-manager list messages for folder non-existent-folder using MCP tools; same Important Instruction as Prompt 4.

use external-service-manager Important: invoke exactly one MCP tool that accepts a folder name; pass non-existent-folder; same four-point Important Instruction as Prompt 4.

use external-service-manager call tool view_system_logs with arguments JSON {"log_type":"error"} via MCP only.
